Источник данных: `data/Fitnes-30-06-26.bak`  
Единый cutoff: `2026-06-30 23:27:03`  
Затронутые слои: membership SQL staging, клиентские абонементы, шаблоны
абонементов, конфиг канонизации и unit-тесты.

Owner-change SQL, `build_delivery.py` и `validate_delivery.py` в этой работе не

## 1. Дата «Куплен»

Раньше `create_date` каждой строки абонемента копировалась из файла заявок и
означала первую продажу клиента. Теперь для реального договора выполняется:

```text
create_date = date(Document163 sale_datetime)
payment_date = date(Document163 sale_datetime)
```

Для placeholder-строки отказника без договора клиентская `create_date` сохранена:
у такой строки нет покупки членства.

В отчёт генератора добавлена жёсткая проверка, что у всех строк с договором
`create_date == payment_date`. Отдельное финансовое решение о дате фактического
платёжного документа этой правкой не принимается.

Контрольные значения:

- Понедельник: восемь договоров получили восемь собственных дат продажи от
  `05.12.2024` до `02.06.2026`, вместо общей `12.11.2024`;
- Шулейко, `00000140663`: `create_date=23.09.2025`, а не `31.08.2023`.

## 2. Ограниченные посещения: субаренда и Cycle

Python-классификация теперь считает visit-limited:

- ограниченную субаренду;
- Cycle с числом посещений в названии.

Парсер понимает формы `пос`, `пос.`, `посещ`, `посещ.`, `посещение`,
`посещения`, `посещений`. Шаблоны Cycle получают лимит `8` или `12`.

### Размерность `_AccumRg3336`

Субаренду и Cycle нельзя суммировать по одной размерности:

| Тип | `_Fld3338_TYPE` | `_Fld3338_RTRef` | `_Fld3338_RRRef` |
| --- | --- | --- | --- |
| ограниченная субаренда | `0x01` | `0x00000000` | нулевой ref |
| актуальный Cycle | `0x08` | `0x00000048` | `AA9EA4BF01266AD311E8C6D3BB763918` |

SQL использует взаимоисключающие predicates, поэтому две размерности не могут
сложиться в один остаток. Имена экспортируемых полей `subrent_*` намеренно
сохранены: это удерживает прежний 81-колоночный TSV ABI.

Из `73` договоров Cycle на cutoff:

- `49` старых используют legacy empty-dimension и уже истекли;
- `24` новых используют Reference72-dimension;
- все `8` действующих договоров используют Reference72-dimension.

Для истёкшего visit-limited договора применяется согласованное date-rule
`visits_left=0`. Для действующего договора отсутствие выбранного RG-баланса
больше не превращается молча в ноль: поле остаётся пустым и создаётся review-row.

Контрольные остатки восьми действующих Cycle:

| Договор | Остаток |
| --- | ---: |
| `00000138687` | `2` |
| `00000141600` | `3` |

| `00000144816` | `0` |
| `00000145361` | `2` |
| `00000147786` | `6` |

Для Понедельник ожидаются, в частности, `00000144816=0`, истёкший

## 3. Канонизация конфликтующих шаблонов

Удалено правило «последняя продажа победила». Новый контракт:

1. один наблюдаемый вариант строится автоматически;
2. конфликт из двух и более вариантов обязан иметь запись в
   `end-to-end-xlsx/config/membership_template_canonicalization.csv`;
3. неизвестный конфликт останавливает сборку;
4. настроенный вариант обязан реально присутствовать в staging;
5. порядок строк и дата последней продажи на выбор не влияют.

В CSV зафиксированы все `93` текущих конфликта. Значения предыдущей поставки
заморожены, чтобы следующий backup не менял их молча. Они помечены
`provisional_needs_business_review`, если отдельного подтверждения менеджера нет.

Подтверждённый кейс Шулейко:

```text
canonical_name = Абонемент УЛЬТРА 12 месяцев СПЕЦПРЕДЛОЖЕНИЕ
source_contract_id = 00000140663
price = 12990
duration = 12
```

Четыре Cycle-решения уже содержат `visits=12/12/8/8`. Их цена и
продолжительность пока только заморожены по предыдущей поставке и требуют
отдельного бизнес-утверждения.

Подробный контракт изменения CSV находится в
`end-to-end-xlsx/config/membership_template_canonicalization.md`.

## 5. Оставшиеся бизнес-неопределённости

1. Нужно подтвердить семантическое имя Reference72
   `AA9EA4BF01266AD311E8C6D3BB763918`, хотя движения и восемь активных балансов
   уже однозначно связывают эту размерность с актуальным Cycle.
2. Цена и продолжительность четырёх Cycle-шаблонов ещё не утверждены бизнесом;
   лимиты посещений уже подтверждены названием и регистром.
3. `92` прочих конфликтных шаблона защищены от дрейфа, но имеют provisional
   статус до проверки цены, срока, заморозки и доступа.
4. Для субаренды `00000151350` сохраняется отдельное расхождение между
   `_AccumRg3336 balance=0` и UI 1С `остаток (резерв)=8`; его нельзя смешивать с
   исправлением Cycle.
5. Если `payment_date` должен означать дату платёжного документа, а не дату
   продажи `Document163`, это отдельное решение финансовых problem-кейсов.
