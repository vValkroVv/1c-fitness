## Основание проверки

Полный снимок `GET /api/v2/client` получен **23.09.2026, 17:59:14–18:02:49 UTC**: 66 009 клиентов на 661 странице, 66 009 уникальных ID, проверка полноты пройдена. [Метаданные и SHA-256 снимка](../output/20260923_fitbase_photo_audit/api_snapshot_metadata.json) позволяют проверить исходный JSONL. Сопоставление использовало полные ФИО и телефоны, затем уникальный номер карты с телефоном. Для 15 дополнительных связей совпали телефон, начало ФИО и положительная сумма исходных оплат с `purchase_amount` единственной подходящей карточки; это сильное косвенное подтверждение, **не математическое доказательство тождества ID**. Остальные 32 строки оставлены неразрешёнными. [Итоговая сводка связей](../output/20260923_fitbase_photo_audit/reconciliation_complete_summary.json).

Проверка интерфейса показала заглушку вместо фотографии у Fitbase ID **63931, 108786, 121918** и загрузку правильных фото у **63368, 63371**. Шесть карточек, отмеченных ранее как пустые, теперь загружают корректные фото; [повторная проверка](../output/20260923_fitbase_photo_audit/six_recheck.json). Чужое фото, сломанная ссылка и обе сильные обрезки также проверены через UI. Для 224 клиентов без фото проверены 189 других карточек с тем же телефоном: фото нашлось в 17 парах, но **ни одного подтверждённого ошибочного прикрепления** исходного снимка к чужой карточке нет. Совпадение телефона само по себе не доказывает тождество; [детали проверки](../output/20260923_fitbase_photo_audit/wrong_card_photo_review.md).

Сравнение содержимого учитывает пересжатие и изменение размера; 164 обрезки подтверждены геометрическим SIFT/RANSAC сопоставлением. Порог для отдельной проверки качества — менее 60% площади исходного снимка в обрезке; визуальный вывод о непригодности сделан только для двух названных аватаров. [Сводка сравнения](../output/20260923_fitbase_photo_audit/image_comparison_final_34520_summary.json) и [построчные результаты](../output/20260923_fitbase_photo_audit/image_comparison_final_34520.csv).

## Воспроизведение и границы вывода

Скрипты: `scripts/fetch_fitbase_clients_api.py` получает снимок GET и проверяет число страниц/ID; `scripts/reconcile_fitbase_client_photos.py`, `scripts/finalize_fitbase_photo_reconciliation.py` и `scripts/apply_remaining47_photo_links.py` воспроизводят связи; `scripts/compare_fitbase_photo_bytes.py` и `scripts/review_fitbase_cropped_photos.py` проверяют файлы и обрезки; `scripts/review_fitbase_photo_wrong_cards.py` проверяет кандидатов с тем же телефоном. Параметры доступны через `python3 scripts/<имя>.py --help`. Для повторной проверки используйте сохранённый снимок и архив; получение нового снимка требует локального файла токена, который в отчёте не приводится. Проверка выполнялась **только на чтение**; карточки Fitbase не менялись.

Вывод относится к состоянию снимка API в указанное время и выборочным проверкам UI. Последующие изменения Fitbase могут изменить результат. Для 32 исходных клиентов связь с конкретной карточкой не доказана; отсутствие либо наличие их фото в Fitbase не утверждается. Для 15 связей по оплатам сохраняется указанная степень уверенности. Автор и механизм появления чужого снимка не установлены.
