# Если что-то упало

Сначала откройте `work/20260630/status.json`. Там записан последний успешный
этап и полный traceback. После этого ищите лог с тем же именем этапа в
`logs/20260630/`.

Ниже перечислены ошибки, которые проще всего узнать по тексту сообщения.

## `Login failed for user`

Проверьте блок `sql` в `config/pipeline.yml`: адрес, порт, имя базы и логин.
SQL Authentication должен быть включён.

Переменная `FITNESS_SQL_PASSWORD` должна быть задана в той же консоли, из
которой запускается Python. Если используется `--password-file`, проверьте, что
в конце файла нет лишней пустой строки.

Сам пароль в лог не записывается.

## `Connection refused` или timeout

SQL Server не отвечает по указанному адресу. Для контейнера проверьте внешний
порт: он не обязан совпадать с внутренним `1433`. В `pipeline.yml` нужен порт,
к которому подключается Python с хоста.

Также проверьте firewall, VPN и состояние самого SQL Server. Пайплайн его не
запускает и не перезапускает.

## `Database preflight failed`

Откройте:

```text
work/20260630/reports/database_preflight.md
```

Обычно причина одна из этих:

- подключение настроено на `master`, а не на восстановленную базу;
- база ещё не перешла в состояние `ONLINE`;
- восстановлен другой backup;
- SQL-логин не видит часть таблиц;
- это другая конфигурация 1С, где номера физических таблиц не совпадают.

## `Permission denied` для schema или table

Одних read-only прав недостаточно. Скрипт материализует тяжёлые выборки в
схеме `fitbase_part2` и создаёт индексы. Логину нужны DDL-права внутри этой
схемы.

Исходные таблицы `dbo` при этом остаются только для чтения.

## В логе есть `unresolved product review rows`

Это предупреждение, а не ошибка. В проверенной сборке осталось 25
диагностических позиций. Все согласованные решения уже лежат в
`config/product_reclassification_decisions.csv` и применяются отдельно.

Не редактируйте этот CSV только ради того, чтобы убрать предупреждение. Для
изменения решений нужна новая договорённость с заказчиком.

## Не совпало количество строк

Сначала снова проверьте SHA-256 backup. Затем сравните даты в
`config/pipeline.yml`, особенно эти две:

```text
membership_cutoff_at: 2026-05-25 08:00:00
services_cutoff_at:   2026-05-25 08:00:00
```

Майская дата здесь правильная для контрольной сборки. Причина описана в
`docs/03_business_rules.md`.

Для исследования другого backup можно добавить `--skip-reference-counts`, но
это отключает только сверку точного количества строк. Такой запуск уже не
повторяет поставку `20260630`.

## Процесс прервали или машина перезагрузилась

После исправления причины можно продолжить с нужного этапа:

```shell
python scripts/run_pipeline.py --resume --start-at <step>
```

SQL-этапы пересоздают свои промежуточные таблицы, поэтому их можно запускать повторно.
Если непонятно, какие промежуточные файлы успели записаться, надёжнее начать
полный прогон заново.

## Excel держит XLSX открытым

На Windows открытый Excel может заблокировать файл. Закройте книги из `work/`
и `output/`, затем повторите этап.

## Закончилось место

Один `stg_sales_all.csv` содержит больше 510 тысяч строк. Весь `work` занимает
около 1,3 GiB. Для нормального запуска лучше иметь 2-3 ГБ свободного места.

Старые рабочие файлы можно удалить так:

```shell
python scripts/clean_runtime.py
```

Команда чистит только `work`, `logs` и `output` внутри этой папки. Backup,
восстановленную базу и SQL Server она не трогает.
