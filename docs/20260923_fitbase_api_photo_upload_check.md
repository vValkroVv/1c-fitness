# Проверка загрузки фото клиента через Fitbase API v2

23.09.2026 по просьбе заказчика проверена возможность добавить исходное фото Падчиной Анны Игоревны в карточку Fitbase #81371 через API-токен. Выполнены только чтение публичной спецификации `GET https://api.fitbase.io/api_v2` и сверка с локальным аудитом; изменений в Fitbase не было.

В официальном Swagger перечислены 49 путей. Путей с `photo`, `image`, `upload` или `file` нет. `PATCH /v2/client/{id}` принимает только `application/x-www-form-urlencoded` с полями `name`, `surname`, `patronymic`, `birth_date`, `manager_id`, `club_id`, `allowed_clubs[]`, `tags[]`, `custom_fields`. Поле `photo` есть в схеме ответа `ApiClientDto`, но отсутствует в схеме изменения клиента. SHA-256 полученной спецификации: `29add945c4c352d602e0de04af5bbf178ee6b2152ed478ddb44ea975c4e9b092`.

**Вывод:** через документированный публичный API v2 загрузить или прикрепить JPEG к существующей карточке нельзя. Наличие API-токена само по себе не создаёт такого метода. Недокументированные внутренние маршруты Fitbase не проверялись; их поддержку и возможность авторизации API-токеном нельзя предполагать. Рабочий вариант для исправления — загрузка `79004611981.jpg` из основного фотоархива через интерфейс карточки [#81371](https://fitnes-imperiya.fitbase.io/clients/view?id=81371) либо подтверждённый Fitbase отдельный метод импорта фото. Загрузку не выполняли.

Источники: [официальная инструкция Fitbase API](https://help.fitbase.io/article/21001), [Swagger UI](https://api.fitbase.io/site/docs_v2), [машиночитаемая спецификация](https://api.fitbase.io/api_v2), [локальная сверка фото](20260923_fitbase_photo_supplement_371_audit.md).
