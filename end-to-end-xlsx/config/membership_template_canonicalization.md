# Канонизация шаблонов абонементов

Файл `membership_template_canonicalization.csv` — обязательный проверяемый
справочник для названий, у которых в staging одновременно встречается больше
одного варианта `price / duration / visits / freeze / branches_access`.

## Контракт сборки

- один вариант названия строится автоматически;
- два и более варианта без строки в CSV останавливают сборку;
- настроенный вариант обязан реально встречаться в текущем staging;
- `source_contract_id` фиксирует договор, по которому принято решение, и на
  проверенной базе должен соответствовать настроенному варианту;
- если договор-источник больше не попал в клиентскую выборку нового backup, но
  сам настроенный вариант по-прежнему присутствует, сборка продолжается и пишет
  это в audit-счётчик;
- порядок строк и дата последней продажи никогда не выбирают шаблон;
- лишние строки конфига для отсутствующих в конкретном backup названий допустимы.

Таким образом, новый backup не может молча поменять существующий шаблон, а новый
конфликт требует явного решения в git.

## Поля

| Поле | Назначение |
| --- | --- |
| `canonical_name` | Отображаемое имя и ключ после нормализации регистра/пробелов |
| `branches_access` | `Все` или `Продажа` |
| `price` | Каноническая стоимость шаблона; ноль является значением, не пропуском |
| `duration` | Каноническая продолжительность в месяцах |
| `visits` | Лимит посещений либо пусто для безлимитного продукта |
| `freeze` | Дни заморозки либо пусто |
| `source_contract_id` | Контрольный договор для воспроизводимости решения |
| `decision_basis` | Основание выбора |
| `review_status` | Статус бизнес-проверки |
| `note` | Пояснение и оставшиеся ограничения |

## Текущий срез 30.06.2026

- в CSV зафиксированы все `93` конфликтующих нормализованных названия;
- для `Абонемент УЛЬТРА 12 месяцев СПЕЦПРЕДЛОЖЕНИЕ` выбран договор
  `00000140663`: `price=12990`, `duration=12`;
- четыре шаблона Cycle получают `visits=12/12/8/8` из названия;
- цена и продолжительность Cycle пока сохраняют значения предыдущей поставки и
  имеют статус `visit_limit_confirmed_other_fields_provisional`;
- остальные замороженные варианты имеют статус
  `provisional_needs_business_review`: это безопасная защита от дрейфа, но не
  заменяет окончательное решение менеджера по цене, сроку и заморозке.

## Как изменить решение

1. Найти все варианты названия в `membership_import_uncertainties.csv` и staging.
2. Подтвердить один вариант по данным 1С/решению бизнеса.
3. Обновить поля CSV, `source_contract_id`, `decision_basis`, `review_status` и
   `note` одним коммитом.
4. Запустить unit-тесты и полную membership-сборку.
5. Убедиться, что configured variant найден, а новый XLSX прошёл валидацию.
