# Подготовка финального переноса, 20.09.2026

## Основание и изменения правил

Пользователь передал уточнения заказчика от 20.09, 13:45–13:49:
«Вечер 20 делать как вечер 21»; в фотоархиве оставить только валидные телефоны,
включая исключение отсутствующего телефона. Эти уточнения разрешают вопросы
из `20260920_telegram_migration_requirements_audit.md`.

Единый рабочий документ — `20260920_final_migration_plan.md`.
Реальное время backup теперь отделено от явно выбранной актуальности.
По умолчанию прежний точный cutoff backup сохранён; сентябрьская команда
явно выбирает +1 сутки. Исторические даты самих операций не изменяются.

## Реализация

- Общий пул из трёх менеджеров; детерминированный выбор по ID, проверка каждого
  значения в финальном XLSX. Корневые и автономные копии обновлены.
- Общий resolver времени; несовпадение дат слоёв вызывает ошибку. SQL документов
  и смены владельцев использует выбранный cutoff; фактический backup_finish
  остаётся в metadata.
- Подготовка нового backup с хешем, HEADERONLY, FILELISTONLY, VERIFYONLY,
  проверкой последнего восстановления в msdb и генерацией конфигурации.
- Фото по фактически передаваемым ID и телефонам: действующие + реактивация,
  только валидные телефоны, только JPEG. Проверка содержимого/CRC/хешей до
  атомарной публикации ZIP; отчёт исключений.
- Фото включены в основной runner; итоговый manifest и READY создаются после
  всех проверок. Каталоги новых запусков не перезаписываются; resume сверяет
  параметры и контрольные входы, отбрасывает устаревшие статусы поздних этапов.
- `scripts/run_fitbase_migration.py` объединяет подготовку и полный запуск,
  безопасно читает пароль из локального env-файла; поддерживает возобновление.
