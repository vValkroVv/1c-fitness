# 9 абонементов для разбора

В этом архиве девять абонементов, по три на каждую из трёх проблем. Мы пока не
меняем правила выгрузки. Сначала нужно понять, что именно хранит 1С и какие цифры по этим
договорам правильные.

Для каждого кейса собрана одна и та же цепочка:

```text
абонемент в 1С -> строка продажи -> платежи и движения -> формула выгрузки -> строка Fitbase
```

## С чего начать

1. Прочитайте этот README до конца. Здесь есть контекст и порядок разбора.
2. Откройте `04_field_mapping_1c_to_fitbase.md`. Там указаны таблицы, поля 1С и формулы, по которым
   получаются 22 колонки Fitbase.
3. Дальше идите по файлам `01`, `02`, `03`. В каждом описана одна проблема и три разных кейса.
4. Откройте `9_test_cases_20260630.xlsx`. Первый лист показывает готовые строки Fitbase, второй
   собирает исходные цифры из 1С.

## Что нужно проверить

По каждому `contract_id` нужен простой итог:

- какая цена абонемента правильная;
- сколько фактически оплачено и сколько осталось;
- какой объект, регистр или документ 1С нужно считать источником этих сумм;
- нужно ли исправлять данные в 1С или править правило выгрузки.

Отдельно нужно подтвердить смысл `_InfoRg3060._Fld3072`, `_InfoRg3060._Fld5963` и движений
`_AccumRg3305` с `_RecordKind=0`. Именно на этих полях расходятся текущая выгрузка, платежи и движения 1С.

## Почему здесь 254 договора, а не 223

В первом списке было 223 договора. Позже выяснилось, что факты абонементов в той сборке были
майскими, а фильтр уже работал на 30 июня. После полного пересчёта на один момент получилось 254:

| группа | было | стало |
| --- | ---: | ---: |
| 1. Цена есть, платёж не найден | 3 | 10 |
| 2. Цена ноль, прямая оплата есть | 41 | 41 |
| 3. В выгрузке есть долг, в названии нет «рассрочки» | 179 | 203 |
| Всего | 223 | 254 |

Три старых кейса из первой группы на правильном срезе больше не являются проблемными:

## XLSX

В книге три листа:

| лист | что смотреть |
| --- | --- |
| `Fitbase_9_cases` | Дополнительная колонка `problem` и 22 колонки такими, как они сейчас уходят в Fitbase. |
| `Диагностика_1С` | Идентификаторы 1С, продажи, платежи, движения, возвраты, переоформления и филиалы. |
| `Памятка` | Краткая версия этого README внутри XLSX. |

Второй лист особенно удобен для поиска в 1С: в нём есть `contract_id`, `client_id`, `_Document163._IDRRef`,
ссылка на продукт, номер продажи и все платежи.

## Что делаем после разбора

Если в 1С неверные данные, их можно исправить и сделать новый backup. Если данные в 1С верные, а мы
читаем не то поле, мы поменяем пайплайн и пересоберём выгрузку.

Для воспроизводимой сборки XLSX:

```bash
python3 end-to-end-xlsx/scripts/37_build_9_test_cases.py
```
