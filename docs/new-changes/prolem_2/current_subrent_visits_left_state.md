Из обсуждений с заказчиком:

- `visits_left` считается на момент среза/backup;
- самое важное - субаренда;

  пустым;
- остаток посещений нужен там, где тренеры покупают субаренду;

## Найденный источник остатка посещений

### `dbo._Document150`

`dbo._Document150` выглядит как документ прохода/посещения:

- `_Date_Time` - дата/время документа;
- `_Fld989_RRRef` матчится с клиентом;
- `_Fld991_RRRef` матчится с конкретным `subscription_ref`;
- `_Fld993` и `_Fld994` выглядят как вход/выход;
- `_Fld995` равен длительности в секундах;
- в 1С-дате нужен сдвиг `-2000` лет, например `4026-05-20` = `2026-05-20`.

По активным финальным `12` строкам прямой матч:

- `12 / 12` договоров имеют события `_Document150` внутри периода абонемента;
- события находятся с `2026-04-27 11:58:46` по `2026-05-23 10:02:25`;
- для каждого события `_Document150._Fld991_RRRef = subscription_ref`
  соответствующего договора субаренды.

### `dbo._AccumRg3336`

`dbo._AccumRg3336` - более надежный слой, чем простое количество документов
`_Document150`, потому что это движение регистра, записанное документом прохода.

По активным `12` строкам:

- все `87` найденных событий `_Document150` имеют движение в `_AccumRg3336`;
- `_AccumRg3336._RecorderTRef = 0x00000096`, то есть recorder - `_Document150`;
- `_AccumRg3336._RecorderRRef` равен `_Document150._IDRRef`;
- `_AccumRg3336._Fld3337_RTRef = 0x000000A3`;
- `_AccumRg3336._Fld3337_RRRef` равен `subscription_ref`;
- `_AccumRg3336._RecordKind = 1`;
- `_AccumRg3336._Active = 0x01`;
- `_AccumRg3336._Fld3339 = 1.000` на каждой строке;
- остальные числовые поля `_Fld3340.._Fld3347` по активным строкам равны `0`.

Дополнительная проверка показала, что `_AccumRg3336` нельзя считать просто
по `subscription_ref`. На каждом договоре есть две приходные размерности:

| `_Fld3338_TYPE` | что видно | как использовать |
|---|---|---|
| `0x01` | приход лимита и расходы от `_Document150` | это размерность остатка посещений |
| `0x08` | второй приход лимита без расходов посещений | не использовать для `visits_left` |

Если сложить обе размерности, приход удваивается: по активным `12` строкам
суммарный лимит из названий `133`, а сырой приход по всем размерностям `266`.
Это ложный баланс. Правильный фильтр:

```text
_AccumRg3336._Fld3338_TYPE = 0x01
_AccumRg3336._Fld3338_RTRef = 0x00000000
_AccumRg3336._Fld3338_RRRef = 0x00000000000000000000000000000000
```

Отдельной таблицы итогов `_AccumRgT3336` или готового поля остатка не найдено:
в базе есть только `dbo._AccumRg3336`. Поэтому остаток нужно считать как
знаковый баланс движений регистра.

Рекомендуемая формула для активных ограниченных строк:

```text
visits_left =
  SUM(
    CASE
      WHEN _AccumRg3336._RecordKind = 0 THEN _AccumRg3336._Fld3339
      WHEN _AccumRg3336._RecordKind = 1 THEN -_AccumRg3336._Fld3339
      ELSE 0
    END
  )
  where:
    _AccumRg3336._Active = 0x01
    _AccumRg3336._Fld3337_RRRef = subscription_ref
    _AccumRg3336._Fld3338_TYPE = 0x01
    _AccumRg3336._Fld3338_RTRef = 0x00000000
    _AccumRg3336._Fld3338_RRRef = 0x00000000000000000000000000000000
    normalized(_AccumRg3336._Period) <= cutoff
```

Для активных строк эта формула совпадает с `limit - used_visits`, потому что
приход на правильной размерности равен лимиту из названия.

Проверка последовательности движений подтверждает ожидаемую механику:

- для `СУБАРЕНДА 15 посещений` видно `15 -> 14 -> 13 -> ...`;
- для `СУБАРЕНДА 12 посещений` видно `12 -> 11 -> 10 -> ... -> 0`;
- для всех `12` активных строк нет отрицательных шагов и нет баланса выше
  лимита.

- `СУБАРЕНДА 10 посещений`: max `_Fld8008 = 16`, больше лимита `10`;
- `СУБАРЕНДА 8 посещений`: max `_Fld8008 = 17`, больше лимита `8`.

У всех активных ограниченных строк эти поля равны `0`, поэтому они не дают
операционный остаток.

### `dbo._AccumRg3233`

Таблица матчится с документами субаренды, но содержит денежные движения:

- суммы `15 000`, `20 000`, `22 000`;
- `_Fld3246` и `_Fld3247` совпадают с ценой/оплатой;
- `_RecorderTRef = 0x0000009A`, то есть это продажный документ, не проход.

Вывод: полезно для денег, не для остатков посещений.

### `dbo._AccumRg3206`

Таблица матчится только по клиенту на части старых строк:

- нет устойчивой связи с конкретным `subscription_ref`;
- значения выглядят денежными или служебными (`9999`, `2000`, `8999`, `1900`).

Вывод: не подходит для `visits_left`.

### `dbo._AccumRg3336` без фильтра `_Fld3338`

Сам регистр `_AccumRg3336` подходит, но только с фильтром правильной
размерности посещений. Сырой баланс по одному `subscription_ref` не подходит:

- по активным `12` строкам лимит из названия = `133`;
- сырой приход по всем размерностям `_AccumRg3336` = `266`;
- причина: вторая размерность `_Fld3338_TYPE = 0x08` дублирует приход лимита,
  но не списывается документами посещений.

Вывод: использовать только `_Fld3338_TYPE = 0x01` +
пустые `_Fld3338_RTRef/_Fld3338_RRRef`.

## Реализованное решение

Правило текущей сборки:

1. Для `12` активных ограниченных строк `visits_left` заполнен по
   знаковому балансу `_AccumRg3336` на правильной размерности:
   приход `_RecordKind = 0` минус расход `_RecordKind = 1`.
2. Для `916` просроченных ограниченных строк `visits_left = 0`.
3. Для `779` безлимитных строк `visits_left` оставлен пустым.

Проверка после регенерации:

- `business_expired_limited_subrent_zero_visits_left`: `916`;
- `rg3336_correct_dimension_balance`: `12`;
- пустых `visits_left` среди ограниченной субаренды: `0`;
- пустых `visits_left` среди безлимитной субаренды: `779`.
