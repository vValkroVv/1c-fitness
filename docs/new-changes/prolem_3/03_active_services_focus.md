# Активные услуги: основной фокус

Рабочий срез: `2026-05-25 08:00`.

## Правило активности

Услуга считается активной, если она связана с экземпляром `dbo._Document163` и:

- либо имеет положительный остаток посещений в `dbo._AccumRg3336`;
- либо имеет дату окончания не раньше cutoff.

Прямые строки продаж из `dbo._Document154_VT1137` без связанного `Document163`
не считаются активными, потому что для них не найден надежный источник остатка
или срока действия.

## Важный вывод

Большая часть активных остатков относится к старым пакетам, особенно к 2020
году. Это не ошибка текущей логики: заказчик зафиксировал правило, что услуга
действующая, если есть остаток количества/посещений. В найденном регистре
`_AccumRg3336` эти остатки положительные, поэтому строки перенесены как
активные.

Если бизнес считает, что очень старые остатки персональных тренировок уже не
нужно переносить, нужен отдельный бизнес-фильтр по году/давности. Сейчас такого
правила в задаче нет.

## Проверка сроков окончания

Да, старые строки сейчас попадают в активные.

Но важно: они попадают не по сроку окончания, а только по остатку посещений.

Проверка финального XLSX и `services_active_rows_audit.csv`:

- активных строк всего: `352`;
- `is_active_by_balance=1`: `352`;
- `is_active_by_date=1`: `0`;
- `end_date` заполнен: `0`;
- `end_date` пустой: `352`.

То есть у этих активных услуг нет надежной даты окончания в найденном источнике.
В `Document163` для таких пакетов часто лежит техническая дата `2001-01-01`,
которую сборка очищает в пустое значение. Активность держится только на
положительном балансе `_AccumRg3336`.

Это нужно отдельно согласовать с бизнесом: переносить ли старые остатки без
срока окончания как активные, или ввести дополнительное правило отсечения,
например по году продажи/давности.
