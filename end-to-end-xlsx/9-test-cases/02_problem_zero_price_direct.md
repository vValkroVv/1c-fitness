# Проблема 2. Цена ноль, хотя прямая оплата есть

## В чём проблема

На срезе 30 июня здесь 41 активный full-абонемент, по одному на клиента.

Во всех 41 строке:

- `_InfoRg3060._Fld3070 = 0`;
- `_InfoRg3060._Fld3072 = 0`;
- строка продажи `_Document154_VT1137._Fld1160 > 0`;
- есть проведённые непомеченные direct-платежи `_Document152`;
- платежи отнесены к целевой продаже через `_Document152_VT1083`;
- сумма уникальных платёжных документов равна сумме строки продажи;
- `_AccumRg3305` показывает закрытие продажи;
- нет проведённого непомеченного возврата `_Document131`.

Один `_Document152` может повторяться из-за нескольких строк связи. После удаления таких дублей цифры получились такими:

| метрика | значение |
| --- | ---: |
| всего договоров | 41 |
| сумма direct-платежей = строка продажи | 41 |
| один платёжный документ | 29 |
| два или более платежей | 12 |
| сумма direct-платежей меньше/больше строки продажи | 0 |

Бесплатными эти абонементы не выглядят. Строка продажи и движения оплаты сходятся, но `_InfoRg3060._Fld3070` и `_Fld3072` остались нулевыми.

## Как строка попала в эту группу

```text
_product_class == "full_subscription"
activation_date <= 2026-06-30
end_date >= 2026-06-30
price == 0
_payment_match_source starts with "direct_doc152"
_document131_posted_unmarked_refund_count == 0
type_of_payment is not blank
```

## Как сейчас формируются денежные поля

Текущая формула не подменяет нулевую цену строкой продажи:

```text
price = _InfoRg3060._Fld3070 = 0
price <= 0 -> amount_of_payments = 0
payment_left = 0
type_of_payment = по способу найденного direct-платежа
```

Противоречие:

```text
итоговый XLSX: price=0, paid=0, payment_left=0, но тип оплаты заполнен
данные 1С: положительная строка продажи и полное закрытие платежами
```

## Что проверить

1. Почему `_InfoRg3060._Fld3070` и `_Fld3072` равны нулю, хотя строка продажи положительна и полностью закрыта?
2. Какое событие 1С должно обновлять `_Fld3070/_Fld3072`, и почему оно не сработало для этих 41 строк?
3. Можно ли массово пересчитать регистр в 1С из продаж и `_AccumRg3305`?
4. При смене владельца цена/оплата должна оставаться на исходном абонементе или переноситься в другой объект?
5. Можно ли для таких строк брать цену из продажи, а оплату из распределённых движений, если возврата нет?

## Какой результат нужен

Если абонементы платные, `_InfoRg3060._Fld3070/_Fld3072` должны сходиться с продажей и движениями. Если так и должно быть, их нужно пересчитать в 1С. Если цена хранится в другом месте, нужно указать таблицу и поле. Тогда мы изменим выгрузку.
