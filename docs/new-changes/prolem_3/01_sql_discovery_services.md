# SQL discovery: услуги

Рабочий срез: `2026-05-25 08:00`.

Задача discovery: найти фактический источник продаж услуг, активных остатков,
дат, цен и оплат по 51 услуге из файла заказчика.

## Начальные гипотезы

1. Справочник услуг/товаров: `dbo._Reference72`.
2. Текущая staging-логика воронок использует:
   - `dbo._Document163` как источник членств/части продуктовых продаж;
   - `dbo._Document152` как платежные документы;
   - `fitbase_part2.stg_sales_all` как объединение платежей и продуктовых
     продаж.
3. Для услуг нужен отдельный слой, потому что часть услуг из списка 51 может не
   попадать в `stg_subscriptions_all` и текущую классификацию абонементов.

## Что нужно проверить

- точные совпадения 51 названия в `dbo._Reference72`;
- продажи этих продуктов в текущих staging-таблицах;
- документы/табличные части, где product_ref из `dbo._Reference72` встречается
  вне `dbo._Document163`;
- регистр остатков/списаний для пакетов тренировок и разовых услуг;
- применимость платежного маппинга из абонементов.

## Найденные источники

### Справочник услуг

Все 51 название из `new-changes/Услуги список нужных.xlsx` найдены в
`dbo._Reference72`.

Особенности:

- `Разовое посещение` имеет 2 product_ref;
- `Медленный класс (10 посещений) двойное предложение` имеет 2 product_ref;
- остальные названия имеют по 1 product_ref.

### Продажи услуг

Основной источник продаж услуг:

```text
dbo._Document154_VT1137._Fld1146RRef -> dbo._Reference72._IDRRef
```

В этом поле найдено `50 468` строк по product_ref из списка 51 до дальнейших
фильтров, после cutoff/posted/marked фильтра в staging осталось `50 221`.

Текущий `fitbase_part2.stg_sales_all` не подходит как полный источник услуг:
он видит в основном продукты, которые также создают `dbo._Document163`
(`Пакет 12`, `Пакет 8` и похожие), но почти не покрывает административные,
разовые, солярий, подарочные сертификаты и утери.

### Клиент услуги

Клиент продажи услуги находится в шапке продажи:

```text
dbo._Document154._Fld1119RRef -> dbo._Reference64._IDRRef
```

Проверка на примере продажи `00000029949`:

```text
_Fld1119RRef -> 000041039 Береснев Денис Сергеевич
```

Поле `dbo._Document154._Fld1131_RRRef` не является клиентом: в проверенном
примере оно ссылается на `dbo._Enum307`.

### Экземпляр пакетной услуги

Для пакетов и услуг, которые создают отдельный экземпляр, строка продажи
ссылается на `dbo._Document163`:

```text
dbo._Document154_VT1137._Fld1148_RTRef = 0x000000A3
dbo._Document154_VT1137._Fld1148_RRRef -> dbo._Document163._IDRRef
```

Пример `Пакет 12 (персональные тренировки)`:

```text
Document154 sale: 00000029949 от 2026-05-22 18:06:33
Document163 service: 00000150559
client: 000041039 Береснев Денис Сергеевич
```

### Остаток посещений

Для связанных через `Document163` пакетных услуг остаток найден в:

```text
dbo._AccumRg3336
_Fld3337_RRRef = Document163._IDRRef
balance = SUM(receipt _Fld3339) - SUM(expense _Fld3339)
```

Пример `Пакет 12 (персональные тренировки)` / `Document163 00000150559`:

```text
receipt: 12
expense: 0
balance: 12
```

Именно этот баланс используется для `visits_left` активных пакетных услуг.

### Что не найдено надежно

Для прямых строк `Document154_VT1137` без связанного `Document163` надежного
остатка посещений не найдено. Поэтому такие строки не считаются активными сами
по себе. Они попадают в клиентский XLSX только как исторический fallback, если
по услуге нет активных строк среди клиентов финального `import_заявки`.

## Проверка услуг без клиентских строк

После расширения fallback вне `import_заявки` была добавлена `Утеря валика`:
у нее есть 1 историческая продажа в `dbo._Document154_VT1137`, но клиент не
попадает в финальный `import_заявки`.

- `Йога (персональная тренировка) 12 пос. (группа до 4 человек)`
- `Йога (персональная тренировка) 12 пос. VIP (1 человек)`
- `Йога (персональная тренировка) 8 пос. (группа до 4 человек)`
- `Йога (персональная тренировка) 8 пос. VIP (1 человек)`

- `Пакет 10 ВИП (персональные тренировки)`
- `Пакет 4 (персональные тренировки)`

Проверены источники:

- `dbo._Document154_VT1137`;
- `dbo._Document154_VT1181`;
- `dbo._Document154_VT1162`;
- `dbo._Document163`;
