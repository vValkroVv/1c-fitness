# Новый backup 2026-06-30: бизнес-заметки

## Применяемые правила

В новом прогоне сохраняются правила, отлаженные на прошлом backup:

- операция `Смена владельца` переносит членство на последнего нового владельца
  до cutoff;
- старый владелец не должен сохранять переданное членство, но сохраняет свои
  остальные членства;
- финальный `import_заявки` использует phone-dedup, оставляет новые заявки без
  телефона вне итогового XLSX и переносит финальные `Новые заявки /
  Неразобранные` в импорт абонементов с тегом `отказники`;
- колонка `филиал` добавляется только в `import_заявки`;
- закрытый клуб `Карельский` в нормализованных/product-club сценариях
  маппится в `Ровио, 3`; историческое исходное значение остается только в
  `raw_club`;
- пластиковые карты экспортируются только для внутренних `Действующие клиенты`;
- импорт абонементов строится по union: финальный `import_заявки` после удаления
  отказников + CSV отказников `new_application_refusers.csv`;
- импорт услуг строится по финальному `import_заявки` после удаления отказников,
  потому что заказчик просил внести отказников только в таблицу абонементов;
- исторические fallback-строки услуг сохраняются по прежней логике;
- активные проблемные XLSX строятся из того же итогового импорта абонементов.

## Осознанное отличие нового прогона

Прошлый отладочный запуск был на майский cutoff `2026-05-25 08:00`.
Для свежего backup выбран cutoff `2026-06-30 23:27:03`, равный времени окончания
backup. Поэтому счетчики строк и состав клиентов ожидаемо могут отличаться.
