# Сверка фотографий Fitbase с поставкой 21.09.2026

## Основание и границы

- Исходный файл: `output/20260921_fitbase_for_customer/fitbase_client_photos_20260921.zip`, 35 422 JPEG и внутренний манифест с ID клиента 1С, телефоном, именем файла и SHA-256.
- По уточнению заказчика исключён список 717 клиентов без карточек. Среди них 646 имели JPEG в архиве. К проверке карточек относится 34 776 фотографий.
- Fitbase проверяется по существующему API v2 только запросами `GET /api/v2/client` и выборочно через интерфейс. Карточки не изменялись.

## Снимок API

23.09.2026 с 17:59:14 до 18:02:49 UTC получены все 661 страница и 66 009 уникальных записей. Повторных ID нет, `total_count` совпал с числом строк. Метаданные и хеш снимка: `output/20260923_fitbase_photo_audit/api_snapshot_metadata.json`. В 34 650 записях API поле `photo` непустое; это общий счётчик всей базы, а не результат сверки поставки.

## Сопоставление клиентов

Исходная сверка требовала совпадения нормализованных полного ФИО и телефона: 33 860 фото присутствовали, 200 отсутствовали, 716 строк требовали разбора. Дополнительная проверка уникального номера карты и телефона связала 669 строк (646 с фото, 23 без). Для ещё 15 строк совпали телефон, начало ФИО и положительная сумма исходных оплат с LTV единственной подходящей карточки (14 с фото, 1 без). Остальные 32 строки не назначались по одному имени либо телефону.

Итог по **наличию**: 34 520 с непустым полем фото, 224 с пустым полем, 32 без надёжной связи. Построчный результат: `output/20260923_fitbase_photo_audit/reconciliation_complete.csv`.

## Проверка через интерфейс

Три карточки из группы с пустым `photo` (ID Fitbase 63931, 108786, 121918) показывают `/css/images/avatar_male.jpg`; детали: `output/20260923_fitbase_photo_audit/missing_review.md`. Две карточки из группы с фото (ID 63368 и 63371) открыты в UI: оба изображения загрузились с `files.fitbase.io`, размеры 300×225; детали: `output/20260923_fitbase_photo_audit/ui_present_examples.json`. Шесть карточек, где 22 сентября были заглушки, сейчас показывают загруженные изображения, все шесть визуально соответствуют JPEG поставки после пересжатия: `six_recheck.json` и `image_metric_calibration.json`.

## Содержимое изображений

Первоначальные параллельные запросы к файловому серверу сбрасывались до фиксации построчных результатов. После перехода на соединения с повторным использованием и построчный контроль получены результаты для всех 34 520 карточек с непустым `photo`: 34 518 изображений относятся к исходному клиенту, одно показывает другого человека, одно отвечает HTTP 404. Итоговые метрики, исправленная классификация и контроль числа строк: `output/20260923_fitbase_photo_audit/image_comparison_final_34520.csv` и `_summary.json`. Исходные метрики сохранены отдельно.

Изображения пересжимаются, поэтому побайтовые SHA-256 обычно не совпадают. Калибровка на шести известных парах и 30 отрицательных перекрёстных парах, сравнение пикселей, визуальная проверка десяти пограничных пар и SIFT/RANSAC для 164 кадров с изменёнными пропорциями оставили ноль неразрешённых случаев содержимого. Два из 164 кадров обрезаны так, что в карточке почти не видно лица: ID Fitbase 83572 и 85913. Полный перечень — `photo_crops_all.csv`; две проверки UI — `ui_crop_issue.json` и `ui_crop_issue_2.json`.

Чужое фото подтверждено у ID 127452; фото не найдено в исходном архиве (`wrong_photo_case_000065590.md`). У ID 104843 фото указано в API, но его URL отвечает 404 и в UI виден битый аватар (`ui_broken_photo.json`). Для 224 клиентов без фото дополнительно проверены 189 других карточек с тем же телефоном; у 17 таких карточек были изображения, но ни одно не оказалось исходным фото отсутствующего клиента.

## Выдача и проверки

- `photo_discrepancies.csv`: 260 уникальных исходных ID — 224 без фото, 1 чужое фото, 1 битая ссылка, 2 сильные обрезки, 32 клиента без доказанной связи с карточкой.
- `photo_crops_all.csv`: 164 кадра с изменёнными пропорциями, из них 2 с подтверждённой проблемой отображения.
- `docs/20260923_fitbase_photo_audit_final.md`: итоговый отчёт и границы выводов.
- Проверены полнота снимка API, уникальность сопоставленных ID, совпадение исходных файлов с манифестом, покрытие всех 34 520 фото сравнением, синтаксис новых скриптов и отсутствие 646 исключённых ID в адресном списке.
- Локальная папка аудита добавлена в `.gitignore`, чтобы снимок API, контактные данные и JPEG не попадали в коммит. Во время проверки токен находился только в `tmp/`, после проверки удалён; в отчёты не включался.
