## Единый срез

Файл применяется только к поставке из backup со следующими значениями:

```text
cutoff_at = backup_finish_at = 2026-06-30 23:27:03
cutoff_date = 2026-06-30
date_stamp = 20260630
```

Конфиг и скрипт падают при несовпадении `cutoff_at`,
`backup_finish_at`, `cutoff_date` или `date_stamp`.

## Сопоставление

В менеджерском файле нет `client_id`. Для текущих данных применено:

1. точное нормализованное ФИО;
2. телефон как обязательная перекрёстная проверка, когда он заполнен;
3. дата продажи для выбора нужного документа у клиента с несколькими
   продажами;
4. неоднозначное совпадение останавливает обработку.

Все `272` нормализованных ФИО уникальны. Среди problem1–3:

| problem3 | `203` | `191` | `12` |
| **всего** | **254** | **192** | **62** |

Для `191` найденной строки совпали ФИО и телефон. Ещё один человек однозначно
совпал по уникальному ФИО при отсутствии телефона в обоих источниках.
Конфликтов или неразрешённых совпадений нет.

## Особенности финансовых значений

`Продано`, `Оплачено` и `Задолженность` считаются тремя независимыми
достоверными полями менеджерского отчёта.

У `38` выбранных строк:

```text
Продано - Оплачено != Задолженность
```

Эти значения не пересчитывались и перенесены дословно. Это прямое следствие
утверждённого бизнес-правила, а не ошибка генератора.
