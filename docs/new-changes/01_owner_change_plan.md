Дата фиксации ответов заказчика: 2026-06-22

## Цель

Исправить баг в текущих выгрузках, когда действующее членство остается привязанным к старому владельцу, хотя в 1С по членству была оформлена операция `Смена владельца`.

Эта проблема влияет на базовые XLSX:

- `output/fitbase_active_clients_import_zayavki_20260429.xlsx`
- `output/fitbase_active_clients_plastic_cards_20260429.xlsx`

И на актуальную part2-сборку, где логика клиента для членства строится по исходной продаже/документу членства:

- `output/part2_20260525_0800_final_combined/fitbase_active_clients_import_zayavki_20260525_0800__all_funnels.xlsx`
- `output/part2_20260525_0800_final_combined/fitbase_active_clients_plastic_cards_20260525_0800__all_funnels.xlsx`

Текущий рабочий срез для реализации: `2026-05-25 08:00`.

## Зафиксированные решения

- Смену владельца применяем строго на cutoff `2026-05-25 08:00`.
- Используем только проведенные документы; непроведенные и помеченные на
  удаление игнорируем.
- Поле `Клиент` в документе смены владельца - старый владелец, поле `Владелец`
  в блоке `Смена владельца` - новый владелец.
- Если у членства несколько смен владельца, берем последнего владельца на
  cutoff.
- Переданное членство должно быть только у нового владельца.
- Остальные членства старого владельца остаются у старого владельца.
- Старый и новый владелец после переноса пересчитываются по обычным правилам
  воронок.
- Текущая phone-dedup логика сохраняется.
- Пластиковую карту для нового владельца берем из его текущей карточки клиента.
- Филиал берем из членства/продажи.
- Финансы переданного членства в будущем импорте абонементов показываем у
  нового владельца.
- Пары `старый владелец -> новый владелец` фиксируем в доп. отчетах, но не в
  импортных XLSX.
- Обычную смену текста ФИО тоже нужно проверить, не только операцию
  `Смена владельца`.

## Проверки после реализации

Обязательные named-case проверки:

- `Успенский Леонид Владимирович` должен перестать быть `Новые заявки` и попасть в `Действующие клиенты`, если членство активно на дату среза.
- `Василевская Вера Михайловна` должна получить переданное активное членство, если оно активно на дату среза.
- `Россиева София Сергеевна` должна получить переданное активное членство, если дата смены владельца попадает в дату среза.
- старые владельцы не должны сохранять у себя эти конкретные переданные членства.
- если у старого владельца есть другие активные членства, они должны остаться у старого владельца.

Общие проверки:

- не должно появиться дублей одного и того же членства у старого и нового владельца;
- сумма членств до/после должна измениться только по владельцу, а не по количеству;
- распределение клиентов по воронкам должно быть пересчитано и задокументировано;
- финальные XLSX должны пройти текущую валидацию;
- отдельно проверить пластиковые карты для новых владельцев.

## Риски

- В 1С смена владельца может храниться не в одном очевидном документе, а в табличной части или движениях регистра.
- Исходная продажа и платежи остаются на старом клиенте. Для будущего импорта абонементов нужно решить, кому показывать оплату/долг: фактическому плательщику или текущему владельцу.
- Часть примеров имеет даты после среза `2026-04-29` или `2026-05-25 08:00`. Для текущего финального среза такие смены владельца могут не попадать в результат, если строго соблюдать дату среза.

2. Найти источник обычной смены ФИО.
