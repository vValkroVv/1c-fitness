## Правила имен файлов

Телефоны нормализованы тем же правилом, что и в принятом XLSX-пайплайне:

- `8XXXXXXXXXX` преобразуется в `7XXXXXXXXXX`;
- десятизначный номер получает префикс `7`;
- из карточки с несколькими номерами выбирается уникальный валидный номер;
- в имени используются только цифры, без `+`, пробелов и скобок.

Распределение:

| Статус | Файлов | Шаблон |
|---|---:|---|
| Основной уникальный телефон | 10 873 | `<телефон>.jpg` |
| Альтернативный уникальный телефон карточки | 11 | `<телефон>.jpg` |
| Общий телефон у нескольких клиентов | 13 | `<телефон>__<ID клиента>.jpg` |
| Невалидное числовое значение | 9 | `INVALID_PHONE_<цифры>__<ID клиента>.jpg` |
| Валидный телефон отсутствует | 20 | `NO_PHONE__<ID клиента>.jpg` |
| Итого | 10 926 | — |

Таким образом, `10 884` файла имеют имя, состоящее точно из уникального
нормализованного телефона. Для остальных `42` файлов суффикс/замена обязательны:
без этого одинаковые имена перезаписали бы фото, а отсутствующие телефоны
пришлось бы выдумывать. Все исключения перечислены внутри ZIP в
`_reports/phone_filename_exceptions.csv`.

## Воспроизводимый скрипт

```text
scripts/41_export_active_client_photos_zip.py
```

Запуск при работающем контейнере:

```bash
python3 scripts/41_export_active_client_photos_zip.py
```

Скрипт:

1. проверяет `BackupFinishDate` и cutoff всех уже построенных слоев;
2. выбирает только воронку `Действующие клиенты`;
3. назначает уникальные телефонные имена максимальным паросочетанием;
4. потоково читает BLOB через BCP;
5. декодирует контейнер 1С и проверяет сигнатуру каждого изображения;
6. пишет изображения сразу в ZIP, не создавая открытую папку с фото на диске;
7. добавляет CSV-манифест с размером и SHA-256 каждого изображения;
8. перечитывает ZIP, проверяет CRC, число фото, число строк манифеста,
   уникальность путей и сигнатуры.

Повторный запуск не перезаписывает существующий архив без явного флага
`--overwrite`.
