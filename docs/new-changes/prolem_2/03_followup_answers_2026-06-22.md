# Follow-up answers: payment type, zero price, subrent, installment

Дата: `2026-06-22`.

## 1. Почему `payment_type` пустой в 34 160 строках

`payment_type` не лежит напрямую в строке членства. В пайплайне он
восстанавливается по ближайшему платежному документу `dbo._Document152` через
`fitbase_part2.stg_sales_all`, затем маппится в допустимые значения
`наличные`, `безналичные`, `сбп`.

Разбор пустых значений:

- всего пустых `payment_type`: `34 160`;
- платежный документ не сматчился: `27 615`;
- платежный документ сматчился, но способ оплаты пустой/не маппится: `6 545`.

Разбор по цене и наличию платежного документа:

- `price=0`, платеж не найден: `24 473`;
- `price>0`, платеж не найден: `3 142`;
- `price>0`, платеж найден, но method не маппится: `6 065`;
- `price=0`, платеж найден, но method не маппится: `480`.

Сырые способы оплаты, которые не были замапплены:

- пустой `payment_method`: `3 392`;
- `Для ошибок, атол 30Ф,Кульманова А.В. ИП`: `2 243`;
- `Для ошибок, Кульманова А.В. ИП`: `835`;
- `БАР ИП Иконников Андрей Анатольевич`: `75`.

Причина: эти значения не являются однозначно `наличные`, `безналичные` или
`сбп`, поэтому скрипт не подставляет тип оплаты сам.

## 3. `visits_left` по субаренде

Всего строк субаренды в итоговом клиентском XLSX: `1 707`.

Из них:

- ограниченная субаренда: `928`;
- безлимитная/без явного лимита в названии: `779`.

До исправления `visits_left` был пустой во всех `1 707` строках субаренды.

Для безлимитной субаренды пустой `visits_left` ожидаем. Проблема относится к
ограниченной субаренде:

- `СУБАРЕНДА 15 посещений`: `449`;
- `СУБАРЕНДА 12 посещений`: `388`;
- `СУБАРЕНДА 8 посещений`: `77`;
- `СУБАРЕНДА 10 посещений`: `11`;
- `СУБАРЕНДА 20 посещений`: `3`.

В шаблонах поле `visits` для этих названий заполнено из названия.

Актуализация после дополнительного разбора: для активной ограниченной
субаренды найден источник остатка - знаковый баланс `dbo._AccumRg3336` по
размерности `_Fld3338_TYPE = 0x01` с пустыми `_Fld3338_RTRef/_Fld3338_RRRef`.
Все активные `12` строк чисто считаются по регистру. После бизнес-решения
просроченная ограниченная субаренда получает `visits_left = 0`; в новой
сборке `916` просроченных ограниченных строк заполнены `0`, `12` активных
строк заполнены балансом регистра, `779` безлимитных строк оставлены пустыми.
Подробности описаны в
`docs/new-changes/prolem_2/current_subrent_visits_left_state.md`.

## 4. Рассрочки

Изначально 3 рассрочки были помечены как требующие проверки, потому что
`dbo._InfoRg3060._Fld3072 = 0`, а по первому правилу именно это поле
использовалось как `amount_of_payments`.

`dbo._Document152`. Правило обновлено: если в названии есть `рассрочка` и
